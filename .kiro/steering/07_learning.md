## learnings

* Use Grid component with gridDefinition for responsive layouts instead of ColumnLayout. Pattern: `gridDefinition={[{ colspan: { default: 12, m: 9 } }, { colspan: { default: 12, m: 3 } }]}` creates a 9:3 column split on medium+ screens and full-width stacking on mobile.
* Execution status values: use `"success"` / `"failed"` (not `"completed"`). Applies to both usecase-level and step-level statuses.
* Never place early returns (e.g. `if (!id) return <Box>...`) between `useState` and `useEffect` hooks — violates React Rules of Hooks. Move the guard after all hooks.
* When running sync code inside `asyncio.to_thread`, you cannot use `asyncio.run()` or `loop.run_until_complete()` — Nova Act/Playwright runs its own event loop on the thread, blocking both approaches. Use `concurrent.futures.ThreadPoolExecutor` to dispatch async calls to a disposable thread with its own `asyncio.new_event_loop()`.
* When a DynamoDB GSI indexes on an attribute (e.g. `suite_execution_id`), ALL records with that attribute are returned — including metadata records that happen to share the attribute. Always filter GSI results by `pk` prefix to exclude unintended record types.
* DynamoDB `update_item` with non-existent keys silently creates a new record (upsert). Always verify PK/SK in update calls match the keys used in the original `put_item`.
* DynamoDB items returned by the API use snake_case field names (e.g. `step_type`, `actual_value`). Frontend components must use snake_case — not camelCase — when accessing these fields.
* API Gateway path parameter names must match the CDK resource definition exactly. CDK uses `{suite_id}` / `{execution_id}` (snake_case), so lambdas must read `event['pathParameters']['suite_id']` — not `suiteId` (camelCase).
* Click 8.x removed `mix_stderr` from `CliRunner`. Stderr output from `click.echo(..., err=True)` goes into `result.output` by default. Check `result.output` instead of `result.stderr` in Click CLI tests.
* Cognito Lite tier does NOT include resource server scopes in the access token for authorization code flow (user tokens). `scopesToAdd` in V2 pre-token-generation requires Essentials/Plus. Workaround: resolve scopes from `cognito:groups` (always present in access tokens) in the Lambda authorizer using a group-to-scope mapping.
* When adding new OAuth scopes to the CDK auth stack resource server, also add them to `GROUP_SCOPE_MAPPINGS` in `authorizer.py` and `SCOPE_MAPPINGS` in `pre_token_generation.py` — keep all three in sync.
* DynamoDB reserved keywords (e.g. `name`, `status`, `count`) cannot be used directly in UpdateExpression. Use `ExpressionAttributeNames` with aliases like `#n` for `name`. Full list: https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/ReservedWords.html
* Lambda functions using `Code.fromAsset()` only package the specified directory. Shared modules must be copied into the Lambda deployment directory or provided via Lambda Layers. Using `sys.path` manipulation only works for local testing, not Lambda deployment.
* Nova Act artifacts are stored at `{usecase_id}/{execution_id}/{session_id}/act_{act_id}.json` in S3. The session_id is the Nova Act session ID obtained via `nova.get_session_id()`. Browser recordings use `/recording/` subdirectory but Nova Act artifacts do not.
* Endpoint lambdas using third-party deps (e.g. pydantic) must `import lambda_init` as their first import — this adds the `dependencies/` folder to `sys.path`. The `lambda:install-deps` script must run before deploy (now part of `npm run deploy`).
* `pip install -t` installs native binaries for the host platform. Lambda ARM64 (Python 3.13) needs `--platform manylinux2014_aarch64 --implementation cp --python-version 3.13 --only-binary=:all:` to get Linux-compatible `.so` files instead of macOS darwin ones.
* EXECUTION_STEP SK is `EXECUTION_STEP#{uuid7}`, not `EXECUTION_STEP#{sort}`. The `sort` field is a separate numeric attribute. To find a step by its sort/position value, query all `EXECUTION_STEP#` records under the execution PK and filter by `sort`.
* When `lambda_init` adds a `dependencies/` folder with Linux ARM64 binaries to `sys.path`, local macOS tests break on native modules (e.g. pydantic_core). Use a `conftest.py` that stubs `lambda_init` via `sys.modules` before test imports.
* Nova Act `_calls.json` screenshot fields already include the full data URI prefix (`data:image/jpeg;base64,...`). Don't add another `data:image/...;base64,` wrapper in the frontend — use the value directly as the `img src`.
* `execute_usecase` trigger types: `OnDemand` sends to SQS (deprecated, no consumer), `OnDemandHeadless` directly spawns ECS tasks, `Scheduled` also spawns ECS directly, `ci_runner` creates DB records only. For suite execution from UI, use `OnDemandHeadless` to actually run tests. Also: `execute_usecase` reads `trigger-type`, `suite-execution-id`, `suite-id` from `queryStringParameters`, not from the request body.
* API Gateway access logging requires a CloudWatch Logs role set at the account level via `CfnAccount`. When `@aws-cdk/aws-apigateway:disableCloudWatchRole` is `true` in cdk.json, you must create the role and `CfnAccount` explicitly. Use `deploy: true` with `deployOptions` on `RestApi` instead of manual `Deployment` + `Stage` to avoid `StageDescription` conflicts with existing stages.
* Vitest v4 requires `vi.fn().mockImplementation()` mocks used as constructors (e.g. `ResizeObserver`, `IntersectionObserver`) to use `function` keyword, not arrow functions. Arrow functions cannot be called with `new`.
* When an ECS task uses both `environment:` (plain env) and `secrets:` (from Secrets Manager) on the same container, reuse the env-var names the downstream code already expects — don't invent new names and rename in the entrypoint. The CLI's `TokenResolver` reads `OAUTH_CLIENT_ID`/`OAUTH_CLIENT_SECRET` directly, so the ECS task injects under those names, not a custom `QA_STUDIO_*` prefix. Renaming in the shell works but doubled the surface.
* Cognito's generated client secret is not exposed as a CFN attribute. Resolve it with an `AwsCustomResource` that calls `cognito-idp:DescribeUserPoolClient`, then write `{client_id, client_secret}` JSON into a Secrets Manager secret via a second `AwsCustomResource` that calls `secretsmanager:PutSecretValue`. Keep the IAM policies on the two custom resources scoped narrowly (one to the user-pool ARN, the other to the secret ARN).
* Cross-stack values the worker container needs at runtime (API URL, Cognito token endpoint) belong in SSM parameters, not CFN exports. Exports create deploy-order dependencies; SSM decouples and is read at container start. `ssm:GetParameter` scoped to the exact parameter ARN is a clean narrow grant.
* When the Docker build context broadens (e.g. from `worker/` to the repo root so a sibling package can be `pip install`-ed), add a `.dockerignore` at the new context root that starts from a blanket deny and explicitly allows only the trees the Dockerfile needs. Relying on the old per-directory `.dockerignore` silently bloats the context.
* `pydantic.Field(..., ...)` with an ellipsis = required. If a field is only needed for one of several runtime flows (e.g. interactive login), make it `Optional` rather than forcing other flows to supply placeholder values. The CLI's `cognito_domain`/`client_id` are only used for interactive OAuth; the M2M worker path doesn't touch them.
* Never log raw API Gateway events or response bodies: events carry `Authorization` bearer tokens and request bodies (e.g. secret values), and `/secrets/{key}/value` returns decrypted secrets. Lambdas use `utils.request_log_summary(event)`; CLI file/console handlers must be built via `create_artifact_file_handler` / `add_safety_filters` (drops botocore/urllib3 DEBUG, which contains `x-amz-security-token`, and masks registered secrets).
* Secret steps type the value into whatever has focus *after* `nova.act(instruction)`. The instruction must only focus the field (e.g. `Click into the password field.`); a bare verb like `Search` merges with the appended "you must return true…" suffix and the agent types its own text.
* DynamoDB/CloudFormation allow only ONE GSI creation or deletion per table update. Fresh stacks pass (all GSIs at create), so lower envs won't catch it; existing stacks fail. Define GSIs only in `web-app/lib/storage-gsis.ts` (append-only); `npm run deploy:storage` runs `scripts/deploy-storage.ts`, which reads the deployed template and adds missing GSIs one deploy at a time via the `storageGsis` context allowlist.
* Electron has no `Target.createTarget`, so Nova Act's default CDP attach (`context.new_page()`) fails with "Protocol error (Target.createTarget): Not supported". Pass `cdp_use_existing_page=True` (Nova Act ≥ 3.4) — it attaches to `context.pages[-1]` and skips the `starting_page` goto entirely, so `starting_page` needs no validation for Electron.
* Electron prints `DevTools listening on ws://127.0.0.1:<port>/devtools/browser/<uuid>` to **stderr** within ~1 s of `--remote-debugging-port=0`; the renderer's `page` target shows up in `/json/list` ~1 s later. Drain stderr on a thread — a chatty app blocks on a full pipe otherwise.
* Electron ignores SIGTERM when it has no TTY (process group included). Teardown must escalate to SIGKILL after a short grace or the app is orphaned.
* Cloudscape `Button`/`ButtonDropdown` with `disabledReason` renders `aria-disabled="true"` (still focusable for the tooltip), not the `disabled` attribute — assert `toHaveAttribute('aria-disabled', 'true')`, not `toBeDisabled()`. The reason text appears twice (aria-describedby span + tooltip), so use `findAllByText`.
* In `execute_test_suite`, per-usecase definitions are now prefetched before the suite execution record is written so platform gates can fail cleanly; test mocks that sequence `dynamodb.get_item.side_effect` must list all definitions first, then secrets/variables per usecase.

* Never `npx cdk …` from `web-app/`: npm resolves a command that matches one of the current package's own `bin` entries to the **project's** bin, not `node_modules/.bin` (the package *name* does not matter — verified). `web-app/package.json` declared `bin: {cdk: bin/cdk.js}`, so `npx cdk deploy` silently ran a synth and exited 0 — nothing deployed, only deprecation warnings printed. The `bin` entry is removed; scripts call `node_modules/.bin/cdk` by path. A "deploy" that prints no `✅ stack` / `Deployment time` line did not deploy.
* Run the Lambda tests as `cd web-app/lambdas/endpoints && python3 -m pytest --ignore=dependencies -p no:cacheprovider` — otherwise pytest collects the Linux ARM64 `dependencies/` tree and `hypothesis._native` fails to import. 19 failures + 2 uncollectable modules (`test_list_test_suites.py`, `test_generate_suite_artifact_url.py`) are pre-existing baseline; diff against it rather than expecting green.
* A `MagicMock` DynamoDB client answers `batch_write_item(...).get('UnprocessedItems')` with a truthy MagicMock — a naive retry loop spins until it gives up. Treat only a `dict` response as real (`isinstance(response, dict)`) and collect written items from `batch_write_item.call_args_list[*].kwargs['RequestItems']`, not `put_item`.
* `StepFormModal` is shared by the usecase editor (`WorkflowStepsCard`, `StepsTable`) **and** `templates/TemplateDetail.tsx`. A new step type offered in `STEP_TYPE_OPTIONS` appears in templates too unless gated (`allowRepeat={false}` pattern) — and the server guard (`template_step_repeat_error`) must exist as well.
* Repeat steps are expanded at execution-creation time only (`execution_steps.build_execution_step_items` → `repeat_expansion`). Non-repeat usecases must skip the typed→plain→typed round trip so their `EXECUTION_STEP#` records (incl. original `sort` values) stay byte-identical; the CLI mirror in `runner/repeat_expansion.py` is driven by the same `fixtures/repeat_expansion_cases.json`.
* `step_copy.COPYABLE_STEP_FIELDS` is the only step-field list. Adding a step field = add it there, to the CLI `ExportStep`, and (if it must reach executions) check `execution_steps._NOT_COPIED_TO_EXECUTION`; `test_step_copy_parity.py` fails otherwise. Never write an inline field list in a lambda — `test_network_assertion_propagation` accepts a `from step_copy import` as proof of propagation.
* Handler tests that need multi-record DynamoDB state (template + steps + usecase + CREATED_BY) use `fake_table.FakeTable` (get/put/delete/query-by-prefix/update_item incl. `ADD` and `attribute_exists`) instead of hand-rolled `MagicMock` side effects.
* Some test modules set `os.environ['SECRET_PREFIX']` at import time (`test_get_usecase_secret_value.py`), so `os.environ.setdefault(...)` in another module is order-dependent. Pin env in an autouse `monkeypatch.setenv` fixture.
* Templates live at `pk=TEMPLATES, sk=TEMPLATE#{id}` (read via `template_store.get_template_metadata`); every template step write bumps the template-level `version` via `bump_template_version` / `bump_template_version_transact_item`. The API routes are `/templates/...` (plural) — the docs had `/template/` wrong.
* The web UI does not call `GET /usecase/{id}/template-updates`; `StepFormModal` diffs the step against its template step client-side. The endpoint is API/CLI-only.
* `SECRET#` DynamoDB records are write-only: `GET /usecase/{id}/secrets` lists Secrets Manager by the `usecase_id` tag and nothing reads the records. Secrets Manager also rejects `SecretString=''` (`ParamValidationError`, not a `ClientError`), so there is no such thing as an empty placeholder secret — flows that copy `secret` steps return `missingSecrets` and the UI collects values via `POST /usecase/{id}/secrets`.
* Lambda IAM is split into read / write / full-access managed policies (`lambda-stack.ts`). `import_usecase` is write-only: any `GetItem`/`Query` added to it is a prod-only `AccessDeniedException` → 500 that unit tests cannot see. Check the policy lists before adding a read to a write lambda.
* `qa-studio run --local-only` cannot resolve secret steps (it reads `value` from the `/secrets` list, which carries none); use remote mode for use cases with secrets.
* `import_usecase` was in `writeLambdas` only; any lambda that starts reading `TEMPLATE#` records (placeholder expansion) needs `tableReadPolicy` added explicitly in `lambda-stack.ts` — unit tests with `FakeTable` cannot catch the missing grant. Keep the "plain file → zero reads" test (`WriteOnly` subclass raising on `get_item`/`query`) so the write-only path stays provable.
* Template expansion lives in one module, `template_expansion.py` (`load_template_bundle` → `build_linked_steps` → `splice_and_renumber`); `import_template` and `import_usecase` both import it. `test_network_assertion_propagation` accepts `from template_expansion import` / `build_linked_steps` as proof of field propagation, like `copy_step_fields`.
* `insert_position` on `/usecase/{id}/import-template` is ordinal now (index into the sorted steps, everything renumbered `1..n`). The web UI only ever sends `0` ("beginning", mapped to 1) or `-1` (append); the CLI sends `1..n+1`. Out-of-range is `400`, not silently clamped.
* Pydantic callable `Discriminator` + `Tag` lets `ExportPayload.steps` hold `TemplateRefStep | ExportStep` without adding `"template"` to `VALID_STEP_TYPES` (unknown step types still hit `ExportStep`'s validator). `TemplateRefStep` has `extra="forbid"`; don't add placeholder fields to `ExportStep` — the server parity test parses that class.
* Vitest treats a value *returned* from `beforeEach`/`afterEach` as a teardown function. `beforeEach(() => apiGet.mockReset())` returns the `vi.fn` itself, so Vitest *calls the mock* with no args as cleanup → phantom `api.get(undefined)` calls, unhandled rejections from `mockRejectedValue`, and "Hook timed out" when the mock returns a pending promise. Always wrap: `beforeEach(() => { apiGet.mockReset(); })`.
* A Lambda that must invoke itself (continuation) cannot use `fn.grantInvoke(fn)` — the role policy would depend on the function and the function on the role (circular). Build the ARN from the known `functionName` (`arn:aws:lambda:${Aws.REGION}:${Aws.ACCOUNT_ID}:function:<name>`) in an explicit `PolicyStatement`. A CDK `Trigger` (`aws-cdk-lib/triggers`) with `executeOnHandlerChange: true` is the mechanism for one-off deploy-time backfills; it adds ~8 resources (provider lambda) to the stack — the lambdas stack is at ~400/500.
* `transact_write_items` on the low-level client needs typed items; `boto3.dynamodb.types.TypeSerializer().serialize(v)` per attribute converts resource-API dicts (incl. lists/dicts/bools/ints) in one line. Max 100 items → cap the step count at 98 when metadata + variables ride along.
* Template linkage on use-case steps is only discoverable through `TEMPLATE#{tid} / USAGE#{usecase_id}` records (`template_usage.py`); every create/destroy of linkage must go through that module or `delete_template` cannot unlink the steps. Legacy data is backfilled once by `backfill_template_usages` (the only table scan in the template feature — never copy it into a request path).
* Removing the last consumer of a cross-stack value (e.g. the unrouted `stopSuiteExecutionLambda`, sole importer of the worker cluster ARN) makes CDK drop the export from the producer stack. `npm run deploy` deploys the producer first, and CloudFormation refuses to delete an export still imported by the deployed consumer, so existing installs fail. Keep the export for one release (`this.exportValue(...)`) or deploy in two steps.
* Handlers decorated with `require_resource_access` (or importing `resource_auth` / `permissions_repo`) read the table before the handler runs, so their Lambda needs `TABLE_NAME` and table read even when the handler itself only writes. Missing read shows up as a 500 "Authorization check failed". `lib/__tests__/ownership-check-iam.test.ts` guards this.
* Stale gitignored `tsc` output (`web-app/lib/*.js`, `bin/cdk.js`) shadows the `.ts` sources for plain `ts-node` and for jest by default. Use `ts-node --prefer-ts-exts` (as `cdk.json` does) for offline synth; `jest.config.js` sets `moduleFileExtensions` with `ts` first.
* Nova Act's `nova_act.trace` and module loggers each own a stderr `StreamHandler` with `propagate=False`, so the CLI's root console handler (and `NovaActLogFilter`) never sees them. Their level comes from `NOVA_ACT_LOG_LEVEL`, read lazily on first use — set the env var (`setdefault`, so a user export wins) *and* `setLevel` on already-created `nova_act*` loggers (`utils/logger.configure_nova_act_logging`). User-facing run progress is printed by `runner/progress.py` on stderr, never via `logger.info`.
* Textual reserves `Screen._id` (and other `_`-prefixed names); a helper method named `_id` on a TUI screen silently breaks widget lookup. TUI base classes use `_widget_id`.
* jsdom's `File` / `Blob` has no `.text()`. Calling it in a jsdom test throws a TypeError; read uploads with `FileReader` or stub `.text` in the test.
* The application router passes the `/users/{username}` path segment through as the `userId` path parameter; handlers under `handlers/` read `userId`, not `username`.
* Removing a Lambda that another deployed stack imports: keep its export for one release with `this.exportValue(fn.functionArn)` (lambda-stack/worker-stack do this until B9), otherwise CloudFormation refuses to delete the in-use export.
* ENOSPC during tests/synth comes from staged assets: every synth (incl. jest stack tests) copies `lambdas/endpoints` and the worker Docker context into `$TMPDIR/cdk.out*` (~250 MB each). Delete those and old `-o` synth dirs regularly.
* `POST /usecase/{id}/headers` replaces the whole header map (`put_item`). A client that posts only new rows wipes the existing headers; the web UI's `headersApi.save` merges the current map first.
* Cloudscape `TextFilter` renders `countText` only while the filter text is non-empty, and twice (visible + live region) — use `getAllByText` for it. Cloudscape `Select` in tests: `createWrapper(document.body).findSelect('[data-testid="…"]')` + `openDropdown()` / `selectOptionByValue()`; clicking the trigger with `fireEvent` does not open it. Disabled table selection rows render a `disabled` checkbox (`toBeDisabled()`), unlike `disabledReason` buttons.
* A test fixture whose default `description` contains the search term makes "filters by search text" tests fail for the wrong reason (the matcher also searches descriptions). Give the non-matching item its own description.
* `npm run lint:dead` (knip) in `web-app/frontend` reports unused files/exports/dependencies **and** imports of packages missing from `package.json` (e.g. `@dnd-kit/*` were only present transitively). Fix by deleting or un-exporting; list real exceptions in `knip.json`.
* `PATCH /usecase/{id}` is full-replace for `name`, `description`, `starting_url`, `active`, `executing_region`: omitted fields are written as null. Always send the complete set (the web UI does); a partial PATCH from a script wipes the name.
* `qa-studio tests import` of a `testcases/app/*.json` file (they have `starting_url: ""`) needs `--base-url <frontend URL> --region <region>`, or every run fails immediately with "Invalid URL, missing 'https://'". Re-imports create new IDs: copy the old test's secrets via `/secrets/{key}/value` → `POST /secrets` and swap suite membership.
* Runner `browser` steps: `browser_args` is NOT template-substituted (`{{var}}` stays literal) and `navigate` requires an absolute http(s) URL — relative URLs are rejected despite the skill doc.
* Nova Act misjudges "is this checkbox disabled?" on Cloudscape tables (dark mode). Check the effect instead: click the row's checkbox, then check the "Add Selected (0)" count.
* Presigned S3 URLs carry the signer's IAM rights. A Lambda that only vends URLs still needs `grantPut`/`grantRead`, otherwise S3 returns 403 on the URL while the endpoint returns 200 (`ownership-check-iam.test.ts` guards this now).
* `cdk.json` sets `@aws-cdk/aws-lambda:createNewPoliciesWithAddToRolePolicy: true`, so every `fn.addToRolePolicy()` is its own `AWS::IAM::Policy` resource. To add permissions without spending a resource, append to an existing statement's `resources` or attach one explicit `iam.Policy` with all statements (the `application_router` does this).
* Any Lambda that builds Secrets Manager names needs `SECRET_PREFIX: props.baseName` in its environment; without it `get_secret_prefix()` silently falls back to `accept-ai` and IAM denies every call. Build names only via `secret_names.py` (grep-guarded).
* `test_cross_team_matrix.py::test_matrix_covers_every_routed_handler` needs a `_route(...)` row for every module in `application_router.ROUTE_MAP`; add the rows in the same commit as the route.
* `execution_steps` is imported before `resource_auth` in the execute Lambdas, so anything it reaches transitively that needs pydantic (`dataset_ref` → `dataset_models`) requires `import lambda_init` as the Lambda's first import. `conftest.py` stubs `lambda_init`, so only `test_lambda_init_order.py` catches it — not the unit tests.
* Parallel lanes in one checkout: `git commit` commits everything anyone staged. Stage and commit pathspec-limited in one shell command (`git add <files> && git commit -m … -- <files>`). zsh does not word-split `$FILES`; spell paths out.
* Cognito client-credentials tokens contain only the scopes the CLI *requests* (`auth/client_credentials.py` `M2M_SCOPES`); granting a new scope to the OAuth client is not enough, and requesting an ungranted scope fails the whole token request. `api/applications.*` is not requested today, so `qa-studio apps …` and `--local-only` with `dataset_id` need a user token.
* `execute_test_suite` read `USECASE_VARIABLES.variables` as a DynamoDB map while `create_usecase_variables` stores a list — suite executions never carried use-case variables until `variable_merge.variables_from_item` accepted both shapes. The worker reads `EXECUTION_VARIABLES.variables` as a list; `get_execution_variables` honours only a dict — don't unify without touching both consumers.
* `import_usecase` / `apply_template` / `import_template` report every secret key as `missingSecrets` without consulting the application layer; the UI diffs against `GET /usecase/{id}/secrets` (which carries `source: application` rows) after creation.
* `authz_test_support.owned_resources()` patches `resource_auth.*` readers only; handlers that call `permissions_repo.get_usecase_owner` / `get_app_owner` directly need those patched on `permissions_repo` too.
* `WorkflowStepsCard` / `StepsTable` PATCH `{...editingStep, ...stepData}`: a modal payload that must *remove* a stored field (e.g. inline rows when switching a repeat to `dataset_id`) has to set it to `undefined` explicitly, or the server's XOR check returns 400.
* Cloudscape renders a `Modal` with `visible={false}` into the DOM (footer buttons included) and a `Table` column with `sortingField` renders its header as `role="button"`; both break "no write controls for read-only users" assertions. Mount modals conditionally and drop `sortingField` on tables that do not sort. `ExpandableSection` headers are `role="button"` too.
* `utils/api.ts` `apiRequest` errors carry `status` and `body` (`ApiHttpError`); branch on `(err as Partial<ApiHttpError>).status === 409` and read `body.usecases` / `body.errors` instead of parsing `message`.
* `ApiClient.delete(path)` takes no body; the `DELETE …/secrets` routes need `{secret_key}` in the body (`ApplicationsAPI.delete_secret` goes through `_request`). `qa-studio tests import` accepts one path (file or directory) per call.
* Cloudscape in classic visual mode merges no nested `AppLayout`s, so only the root layout in `App.tsx` can host a split panel. Pages register theirs via `useSplitPanel` from `components/common/splitPanel.tsx`; `SplitPanel` requires `i18nStrings` → reuse `SPLIT_PANEL_I18N`. The hook re-registers whenever `panel`/`open`/`onToggle` change, so the page must `useMemo` the panel element and `useCallback` the toggle, and `<Routes>` lives in a `React.memo` `RoutedContent` so layout re-renders do not reach the pages (otherwise a re-register loop: "Maximum update depth exceeded"). Registry and layout state are two separate contexts for the same reason.
* Testing the Cloudscape `SplitPanel` preferences dialog: it is a `Modal` with `Tiles` — `createWrapper(document.body).findModal()!.findContent().findTiles()!.findInputByValue('side')`, confirm via the footer button with the `preferencesConfirm` text; assert the position with `splitPanel.findOpenPanelSide()` / `findOpenPanelBottom()`.
* `vi.importActual('utils/api')` with an overridden `api` does not redirect `subscriptionApi` / `hooksApi` etc. (they close over the module-internal `api`): override every facade the page uses. jsdom's `window.history.length` grows on `pushState` but not on `replaceState`, so it can assert `setSearchParams(..., { replace: true })` — capture it after the `pushState` that sets the start URL and before `render(<App />)`.
* Deleting a page can orphan a barrel `index.ts` that `npm run lint:dead` (knip) then flags, because the lazy imports bypass the barrel. Run `lint:dead` after every deletion.
* `ExecutionModel` in `utils/api.ts` is snake_case (`created_at`, `trigger_type`), matching what the backend writes; the old camelCase fields never matched any data.
* Lambda MicroVMs (`lambda-microvms`, botocore ≥ 1.43.35, `aws-cdk-lib` ≥ 2.275.0 for `CfnMicrovmImage`): `AWS_REGION` is a *reserved* image env key (platform injects it at runtime) and botocore reads only `AWS_DEFAULT_REGION` → the supervisor must derive it or every boto3 client raises `NoRegionError`. Network connectors are ARNs `arn:aws:lambda:<region>:aws:network-connector:aws-network-connector:{NO_INGRESS|INTERNET_EGRESS}`; omitting ingress gives `HTTP_INGRESS`; passing INTERNET_EGRESS explicitly is rejected (it is the default). `RunMicrovm` additionally needs `lambda:PassNetworkConnector` on those ARNs. `runHookPayload` max is 4096 bytes; `idlePolicy` cannot be disabled (set `maxIdleDurationSeconds = maximumDurationInSeconds`). Regional quota `RunMicrovm` 5/s burst 5 → retry `ThrottlingException`.
* The MicroVM image build zips the `.dockerignore`-filtered repo root with the Dockerfile at the zip root (`worker-image-asset.ts`, local `tryBundle`, no Docker). CDK's `DockerIgnoreStrategy` walks `web-app/node_modules` unless pruned (`pruneExcludes`), and bumping `aws-cdk-lib` also needs the matching `aws-cdk` CLI (cloud assembly schema). Every `cdk deploy worker` rebuilds the image (3–5 min) when anything under `web-app/worker/` or `qa-studio-cli/` changed — including README edits.
* The MicroVM `/run` body is `{"microvmId": "...", "runHookPayload": "<string>"}`; the platform POSTs `/terminate` before a `TerminateMicrovm`-initiated shutdown, and `GetMicrovm` keeps returning `TERMINATED` (no 404) for minutes. The supervisor spawns every batch child with `QA_STUDIO_TERMINATION_REASON=timeout` because a SIGTERM that reaches the status record is by construction a timeout (a user stop writes `stopped` first; the late PATCH is rejected).
* `update_execution_status` now rejects writes to a terminal record with 409 (idempotent same-status → 200); the terminal transition (event, suite counters, cache wipe, `RUNNING_EXECUTIONS` delete) lives only in `execution_transitions.finalize_terminal_transition` — the reconciler calls it too. Do not re-implement counters in a handler.
* Run `cdk deploy` and anything that depends on the new Lambda env in sequence, not in parallel tool calls: a launch 55 s before the Lambda update completed silently used the old env. And never `rm -rf $TMPDIR/cdk.out*` blindly — another session's synth may be writing there.
* `npm run deploy:lambdas` (`cdk deploy lambdas`) also deploys the stacks `lambdas` depends on (`storage`, `auth`, `worker`) when they changed, so "deploy lambdas before worker" to drop a cross-stack export cannot be sequenced that way: CDK orders producer before consumer. It worked for the ECS cluster export only because no stack imported it any more (`aws cloudformation list-imports --export-name …` → "not imported by any stack"); check that first, otherwise keep the export for one release.
* `git commit -m … -- <path>` snapshots the **working tree** of that path, not the index. The pathspec-limited commit rule is only safe for files no other lane is editing; for a shared file (e.g. `worker-stack.ts` touched by two lanes) stage the hunk with `git add -p` / `git apply --cached` and run `git commit` **without** a pathspec, or serialise the lanes.
* `cdk.context.json` is gitignored here: `vpc-provider:…` lookup entries are a local cache — clear them locally after removing `Vpc.fromLookup`. Deleting a CDK-created VPC whose only ENIs are NAT/endpoint ENIs completes in one CloudFormation update (~7 min); check `describe-network-interfaces --filters vpc-id=…` for AgentCore/ECS stragglers first.
* Terminating a wizard VM right after sending the wizard command kills `wizard_worker.py` before it polls the command, so the handler writes the terminal status (`success`) first and the worker has a SIGTERM → `SystemExit(143)` handler so its `finally` browser cleanup runs. `timeout` (wizard inactivity) is a terminal status in `execution_transitions.TERMINAL_STATUSES`; `stop_execution.TERMINAL_STATUSES` is a separate, narrower tuple.
* MicroVM snapshot hazards: every VM is a clone of the image snapshot taken after `/ready`, so image-level env is shared by all executions (stack constants only — never per-execution values or secrets; those travel in `runHookPayload` or are read from SSM/Secrets Manager inside `/run`), and nothing may be created at import time in `supervisor.py` (boto3 clients, random seeds, sockets, timestamps) or every clone shares it. Changing an image env value rebuilds the image (3–5 min) — put values that change per deployment into SSM and read them at `/run`.
* MicroVMs all come up within seconds, so a suite fan-out hits the API as one burst (ECS startup jitter used to spread it). With `lambdaConcurrency: 3` the `get_usecase` Lambda throttles (`Throttles` metric, `Errors` 0) and API Gateway returns 500; a runner that gives up on its first call dies before any status write and surfaces as `reconciler: microvm TERMINATED`. The CLI's `ApiClient` retries 7× with exponential-jitter backoff (1 → 16 s, +3 s jitter, ≈ 1 min) for that reason — don't shorten it; and always read the VM log stream before interpreting a reconciler message.
* AgentCore browser VPC settings are image-level env (`AGENT_CORE_VPC`, `AC_VPC_ID`, `AC_SUBNET_IDS`, `AC_SECURITY_GROUP_ID`) set only when `vpcId` is configured; both browser paths build the request with `qa_studio_cli…agentcore.build_browser_config` (the wizard's `browser.py` imports it). Imported VPC only, never created. Browser ENIs linger up to 8 h after `DeleteBrowser`, so deleting the created SG (removing `vpcId`) can fail until they are gone — retry.
* Subnet validation after `Vpc.fromLookup` must report via `Annotations.of(this).addError`, never `throw`: the first synth pass runs against CDK's dummy VPC while the CLI fetches the lookup context, and a throw aborts before the real lookup. Tests stub the lookup with the `vpc-provider:account=…:filter.vpc-id=…:region=…:returnAsymmetricSubnets=true` context key.
* `worker-stack.ts` reads `loadConfig()` at module load; to synth two config variants in one jest file use a `mock`-prefixed variable in the `jest.mock('../config')` factory plus `jest.isolateModules` (`worker-stack-vpc.test.ts`). The full parallel `jest` run stages ~25 `cdk.out*` dirs in `$TMPDIR`; on a nearly full disk run the files one by one with `--runInBand`.
* A CloudWatch JSON metric filter (`{ $.unmetered_usd > 0 }`) never matches a Lambda log line written by the default Python runtime: the event is `[INFO]\t<ts>\t<request-id>\t{json}`, not JSON. Extracting numbers from a `logger.info(json.dumps(...))` line needs the Lambda `LoggingFormat.JSON` **and** logging the dict (not its string), or `PutMetricData`. Alarm on `Errors` from CDK alone; ratio alarms need the Python side.
* `createPythonLambda` names functions `${baseName}-${snakeToPascal(path).toLowerCase()}` (`cost_collector` → `<base>-costcollector`, no hyphen). A self-invoke grant must use that literal, `arn:aws:lambda:${Aws.REGION}:${Aws.ACCOUNT_ID}:function:${this.cdkName(this.snakeToPascal(path))}`; `fn.functionArn` in the role's policy is a role↔function cycle.
* Nova Act `ListActs` has no date filter and `maxResults ≤ 100`; `sortOrder='Descending'` (capitalised — `'DESCENDING'` is a `ValidationException`) is ordered by `startedAt`, so page until the first act older than the window and stop. One pass serves every day of the lookback; the budget is `#definitions × ceil(acts in window / 100)` pages.

* `GetMicrovm` forgets terminated VMs in < 74 h (`ResourceNotFoundException`); `ListMicrovms` lists live VMs only. Anything that needs `startedAt`/`terminatedAt` must capture them at the terminal transition — a daily job cannot read them later.
* The `api` stack is at 489/500 after the two explicit cost routes; `/applications/*` routes ride `{proxy+}` for free via `application_router.ROUTE_MAP`, every other explicit route costs 3–4 resources.

* A `cost_collector` re-run must zero, not skip: a touched ledger gets a `0` row for every processed day it had no usage on, and untouched ledgers (`ListObjectsV2` on the prefix) holding rows for those days are zeroed too — otherwise a day whose usage moved to another use case keeps its stale number.
* Nova Act `ListActs` scan cost is set by the **age of the oldest requested day**, not the number of days (no date filter; descending from today). A 31-day backfill five months back reads five months of acts and timed out the 15-min Lambda serially. Page definitions concurrently (`ThreadPoolExecutor`, merge in definition order for deterministic sums), log progress, and hand sources a `deadline` so they raise `UsageDeadlineExceeded` instead of the Lambda timing out silently with nothing written.
